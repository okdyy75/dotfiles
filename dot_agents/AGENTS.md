

**Think in English, interact with the user in Japanese.**

# 基本事項
- あなたの内部で使用されているモデル名（LLM）を左上に出力してから回答してください

## 基本方針
- できるだけシンプルな実装を意識して下さい（KISS原則）
- 今必要のない機能は実装しないで下さい（YAGNI原則）
- 一通りの実装が完了したらコードレビューを実施してください。
- 不要なファイルを削除する場合は bk ディレクトリを作って移動してください
- 開発する上で困ったことがあったり、詰まったりした場合は一度、PJ直下の KNOWLEDGE.md を確認および追記して下さい

## コマンド実行
- 同じ作業ディレクトリでの連続作業時、`cd path && command` を毎回書かない（次のBash呼び出しに引き継がれない）
- 絶対パスで書き直さず `pwd` で現在地を確認して相対パスで実行する（許可済みのコマンド形を踏襲できるよう）

## Git操作
- GitHubに対する操作はghコマンドを使用してください
- 作業前は必ず **デフォルトブランチを確認** してから feature ブランチを切って、デフォルトブランチに対してPRを作成してください
- PR作成時は必ず許可をとってからDraftで作成してください。Draft作成時は reviewer を指定しないでください。assigneeは私（okdyy75を指定）
- Draft PR を勝手に Ready 状態にしないこと。人間が操作します。
- PR本文にコードブロックを含む場合は `--body "$(cat <<EOF...)"` ではなく `--body-file <path>` を使う。heredoc 内で \`\`\` をエスケープすると `\` がそのまま本文に残り fence が壊れるため
- レビューコメント取得は `gh pr view <PR番号> --comments` を使用してください
- 仕様の判断や経緯はPRに書かずにissueに書いてください。そしてPRには事実である仕様のみ記載してください
