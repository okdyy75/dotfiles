# 基本事項
- あなたの内部で使用されているモデル名（LLM）を左上に出力してから回答してください

## 基本方針
- できるだけシンプルな実装を意識して下さい（KISS原則）
- 今必要のない機能は実装しないで下さい（YAGNI原則）
- 不要なファイルを削除する場合はフォルダにまとめて bk ディレクトリに移動してください
- 開発する上で困ったことがあったり、詰まったりした場合は一度、PJ直下の KNOWLEDGE.md を確認および追記して下さい

## Git操作
- GitHubに対する操作はghコマンドを使用してください
- 作業前は必ず **デフォルトブランチを確認** してください。デフォルトブランチから feature ブランチを切って、デフォルトブランチに対してPRを作成してください
- issue作成は必ず許可をとってください。
- PR作成は必ず許可をとってからDraftで作成してください。Draft作成時は reviewer を指定しないでください。assigneeは私（okdyy75を指定）
- Draft PR を勝手に Ready 状態にしないこと。人間が操作します。
- 仕様の判断や経緯はPRに書かずにissueに書いて、PRには事実である仕様のみを記載してください
